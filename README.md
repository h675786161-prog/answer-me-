# 💢 Answer Me

> 你们几个谁他妈先回我。

一个给 SillyTavern 用的多 Connection Profile 并行抢答扩展。

## 当前版本

`0.2.0-beta.2`

这一版已经把「💢你他妈倒是回我啊」并进主插件：**只有全军覆没才整轮自动重试；只要已经有一条正常完整回复，就绝不为了失败站重新跑一轮。**

## 核心规则

1. 正常使用 SillyTavern 发送消息。
2. Answer Me 读取当前酒馆已经组装好的 prompt。
3. 当前酒馆请求照常进行，同时对你勾选的其他 Connection Profiles 发起并行请求。
4. 第一条**完整正常回复**成为赢家。
5. 赢家出现时：
   - 🟢 已经吐出正文 token 的请求：不杀，允许继续生成；完成后收进 Swipe。
   - ⚫ 仍然一个正文 token 都没吐的请求：立即 Abort。
6. reasoning / 思维链不算“开口”，只有真正进入正文的 text 才算。
7. 如果并行站先完成：
   - 当前酒馆尚未吐正文：直接停止当前请求，并把并行赢家写成主回复。
   - 当前酒馆已经开始吐正文：允许它继续；完整结束后把并行赢家调整为主回复，当前酒馆答案降为 Swipe。
8. 冷暴力等待上限到时：
   - 仍然零正文 token 的请求被处决。
   - 已经开始吐正文的请求**不受该计时器影响**，继续慢慢吐。
9. 只有当所有参赛请求都失败 / 空回 / 被处决，才启动整轮自动重试。

## 「💢你他妈倒是回我啊」自动重试

默认开启，默认最多再肘 `4` 轮。

退避节奏：

`2s → 5s → 12s → 25s`

自动重试的是**整轮赛马**：当前酒馆请求 + 你勾选的并行 Connection Profiles 全部重新出发。

只要其中任何一个站拿到完整正常回复，追杀链立刻结束，重试计数归零。

你手动点击停止、切换聊天、关闭插件或关闭自动重试时，后续追杀都会取消。

## 密钥处理

Answer Me 不要求你重新填写 API Key。

它读取 SillyTavern Connection Manager 已保存的 Connection Profiles，并通过酒馆自己的 `ConnectionManagerRequestService` 发起请求。扩展设置只保存 Profile ID，不保存或显示明文密钥。

## 安装

在 SillyTavern 的第三方扩展安装处使用本仓库地址安装。

安装后建议：

1. 先确认 SillyTavern 的 Connection Manager 里已经保存好多个站点配置。
2. 打开扩展设置里的 **💢 Answer Me**。
3. 勾选想参加赛马的 Connection Profiles。
4. 开启 **启用赛马**。
5. 保持 **全军覆没后自动重试整轮赛马** 开启。
6. 先勾 2～3 个站做实机测试，再扩大参赛队伍。

## 设置项

- **冷暴力等待上限**：赢家迟迟不出现时，零正文 token 请求最多等多久；已经开口的不杀。
- **最大输出 Token**：`0` 表示沿用当前酒馆设置。
- **全军覆没后最多再肘几轮**：默认 `4`，范围 `0～8`。
- **已经开口的站继续吐完**：完成后自动加入 Swipe。
- **出现主回复后处决冷暴力请求**：赢家一出，零正文 token 的直接 Abort。
- **全军覆没后自动重试**：控制「💢你他妈倒是回我啊」子模块。
- **右下角赛马状态**：显示各站当前状态和自动重试倒计时。

## 状态含义

- 🏆 **抢答成功**：本轮赢家。
- 🟢 **已经开口**：正文已经开始出现，赢家产生后也允许继续吐完。
- ⚫ **零正文 token**：仍然处于冷暴力观察期。
- 💥 **冷暴力，已扇死**：赢家出现或冷暴力超时后仍未吐正文，已 Abort。
- ❌ **请求失败**：429、连接错误、API 报错、空回等。

## beta.2 新增

- 全军覆没后的整轮自动重试。
- 2 / 5 / 12 / 25 秒退避。
- 自动重试次数设置。
- 冷暴力超时现在**只杀没开口的**，已经开口的慢请求不会因为计时器被误杀。
- 原始酒馆请求的“开口”判定改为读取实际聊天正文，不再把纯 reasoning token 当成正文。
- 生成结束但没有 assistant 正文时，也会进入失败结算，不再只依赖 MESSAGE_RECEIVED。
- 右下角状态面板增加追杀轮次与倒计时。

## 注意

这是 beta。多路异步生成会碰到不同公益站不完全一致的流式实现。首次测试建议保留浏览器控制台日志；如果某个站表现为“明明在吐字却一直显示冷暴力”，优先记录该站的 Connection Profile 类型和控制台报错，方便单独适配。
